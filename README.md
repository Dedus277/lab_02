# streamstats

Лабораторная 2. Программа читает файлы с событиями (CSV или JSONL), считает по ним
статистику и записывает отчёт в JSON.

Файлы читаются построчно, поэтому большие логи не забивают память.

## Установка

Нужен Python 3.10 или новее. Из папки проекта:

```
python -m pip install -e .
python -m pip install pytest ruff
```

Обратите внимание на точку в конце первой команды. Без неё (`pip install streamstats`)
pip скачает из интернета чужой пакет с таким же названием, и ничего не заработает.

## Как пользоваться

```
python -m streamstats analyze log.csv --format csv
python -m streamstats analyze a.csv b.csv --format csv --output report.json
python -m streamstats analyze events.jsonl --format jsonl --skip-invalid
python -m streamstats analyze events.jsonl --format jsonl --top 10
```

Можно указать несколько файлов, тогда статистика считается по всем сразу.
Если не указать `--output`, отчёт выводится на экран.

Проверки:

```
python -m pytest
python -m ruff check .
python -m streamstats --help
```

## Какие события принимаются

У каждого события четыре поля:

- `timestamp` - дата и время в формате ISO 8601, например `2024-05-01T10:00:00Z`
  или `2024-05-01T13:00:00+03:00`. Если часового пояса нет, считается что это UTC.
  В отчёте всё приводится к UTC.
- `level` - один из `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`, большими буквами.
- `source` - откуда пришло событие, не пустая строка.
- `message` - текст сообщения (может быть пустым).

В CSV первая строка это заголовок с названиями этих полей, порядок колонок любой.
В JSONL на каждой строке один JSON-объект. Кодировка UTF-8, русский текст работает.

## Что в отчёте

Общее число событий, число обработанных файлов, число пропущенных строк, количество событий
по каждому уровню и по каждому источнику, топ источников с ошибками (уровни ERROR и CRITICAL),
время первого и последнего события.

Если файл пустой, получится отчёт с нулями, а вместо дат будет `null`.
Если у источников с ошибками одинаковое число, они идут по алфавиту, поэтому порядок
всегда один и тот же.

## Что делается с плохими строками

Обычно программа останавливается на первой плохой строке, пишет в stderr, где именно
ошибка (например `log.csv:8: field 'timestamp': invalid date вчера`), и завершается
с кодом 2. Отчёт в этом случае не создаётся.

С флагом `--skip-invalid` плохая строка пропускается, в лог пишется WARNING, а общее
число пропущенных строк попадает в отчёт. Остальные строки считаются как обычно.

Если в заголовке CSV нет одной из нужных колонок, программа останавливается даже
с `--skip-invalid`, потому что все строки были бы неверными.

Коды возврата: 0 - всё прошло, 1 - проблема с файлом или диском, 2 - плохие данные
или неправильные аргументы.

## Как устроен код

В папке `src/streamstats`:

- `__main__.py` - разбор командной строки и коды возврата
- `parsers.py` - чтение CSV и JSONL
- `models.py` - класс события и проверка его полей
- `analysis.py` - подсчёт статистики
- `report.py` - сборка отчёта и вывод в JSON
- `errors.py` - свои исключения

Работает это так: читалка из `parsers.py` берёт одну строку файла, `models.py` проверяет её
и делает событие, `analysis.py` прибавляет его к счётчикам, и событие забывается.

Читалки сделаны как генераторы (через `yield`), они отдают события по одному.
Если строка плохая, читалка вызывает `bad_line`: в обычном режиме та бросает ошибку,
а с `--skip-invalid` пишет предупреждение, и читалка отдаёт `None`. Каждый `None`
в `analyze_files` считается пропущенной строкой.

## Про память

Файл читается циклом `for line in file`, то есть по одной строке. Нет `read()`,
`readlines()` и `list(file)`. Сами события нигде не накапливаются: в `Stats` лежат только
счётчики.

Поэтому памяти нужно немного, и она не зависит от размера файла. Она зависит от числа
разных источников, потому что для каждого из них хранится свой счётчик (плюс одна текущая
строка). Я проверял через `tracemalloc`: на файле 18 МБ и на файле 147 МБ пик был
примерно одинаковым, 60-80 КБ.

Исходные файлы открываются только на чтение. Записать отчёт в тот же файл, что и вход,
программа не даёт.
