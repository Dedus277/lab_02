# streamstats

Программа читает события из CSV и JSONL **по одной строке**, считает статистику и пишет JSON-отчёт.

## Как запустить

```bash
python -m streamstats analyze a.csv b.csv --format csv --output report.json
python -m streamstats analyze events.jsonl --format jsonl --skip-invalid
python -m streamstats analyze events.jsonl --format jsonl --top 10
```

Проверки: `python -m pytest`, `ruff check .`, `python -m streamstats --help`
(перед этим один раз `pip install pytest ruff`).
Если не указать `--output`, отчёт печатается на экран.

## Какое событие считается правильным

* `timestamp` - дата ISO 8601 (`Z` и `+03:00` можно; без пояса считаем UTC; всё переводим в UTC)
* `level` - `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` (только большими буквами)
* `source` - непустая строка
* `message` - строка (может быть пустой)

CSV: первая строка - заголовок. JSONL: один JSON-объект на строку. Кодировка UTF-8.

## Что с плохими строками

* **Обычный режим:** останавливаемся, в stderr пишем `файл:строка: field 'поле': причина`, код возврата 2, отчёт не создаём.
* **С `--skip-invalid`:** строку пропускаем, пишем WARNING, число пропущенных попадает в отчёт.
* Если в заголовке CSV нет нужной колонки, останавливаемся в любом режиме.

Коды возврата: 0 - всё хорошо, 1 - проблема с диском, 2 - плохие данные или аргументы.

## Из чего состоит

* `errors.py` - наши ошибки
* `models.py` - событие `Event`, список уровней, проверка записи
* `parsers.py` - читалки `read_csv` и `read_jsonl` (генераторы с `yield`)
* `analysis.py` - класс `Stats` со счётчиками и главный цикл `analyze_files`
* `report.py` - сборка отчёта и JSON
* `__main__.py` - командная строка

Путь данных: файл -> читалка (одна строка) -> `Stats.add` (числа) -> отчёт.

Как работают два режима: когда читалка находит плохую строку, она вызывает `bad_line`.
В обычном режиме та поднимает ошибку, с `--skip-invalid` пишет WARNING, а читалка отдаёт `None`.
`analyze_files` считает каждый `None` как пропущенную строку.

## Потоковость и память

* Построчное чтение: `for number, line in enumerate(file)` в `read_jsonl` и `for row in reader` в `read_csv`.
  Нет `read()`, `readlines()` и `list(file)`.
* `Stats` хранит только счётчики, сами события не сохраняются.
* **Сколько дополнительной памяти:** она зависит от числа *разных источников*, а не от числа событий
  (плюс одна текущая строка). Я мерил `tracemalloc`: файлы 18 МБ и 147 МБ дали пик 57-80 КиБ.
* Исходные файлы открываются только на чтение. Записать отчёт поверх входного файла нельзя.
